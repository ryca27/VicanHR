Summary Troubleshooting

Troubleshooting local access

Start from the VicanHR repository root. If the documentation server is down, open vicanhr-update.html directly in your browser and select Troubleshooting.

1. The documentation page won’t open

python3 -m http.server 8765 --bind 127.0.0.1 --directory Frontend/.angular/local-docs

Keep the terminal tab open. If you see Address already in use, try opening the pages first. The documentation server may already be running.

  • VicanHR update
  • Frontend developer handoff

2. The payroll page won’t open

Start Angular in a separate terminal tab.

cd Frontend
npm start -- --host 127.0.0.1 --port 4200

If Angular reports missing dependencies, run npm ci from Frontend and retry. Once the build finishes, open the payroll cutoff demo.

3. Payroll opens but sign-in or data loading fails

Check whether Django responds through Angular.

curl -i http://127.0.0.1:4200/api/auth/csrf/

If the request fails, return to the repository root, check Colima, and start it if it’s stopped. Then start the backend.

colima status
# Run the next command if Colima is stopped.
colima start

docker-compose -f Backend/compose.yaml up --build -d

Retry the curl command. HTTP 200 confirms Angular can reach Django. If it still fails, check the backend logs.

docker-compose -f Backend/compose.yaml logs --tail=80

Use 127.0.0.1 consistently when signing in and opening payroll pages so your browser uses the same session cookies.

Backend

  • Django and PostgreSQL run locally through Docker Compose.
  • Session login supports admin, finance, HR, and operations. Admin and finance can submit attendance and access payroll drafts.
  • Attendance uploads use the Excel Summary tab or structured JSON. Revisions update matching employees in the same detachment and cutoff.
  • The SMCO draft API calculates gross pay, deductions, and net pay from uploaded workbooks. See the payroll calculation status below for the sample results and remaining work.

Frontend

  • The login screen fits the browser viewport and connects to Django.
  • Upload a Summary CSV or a multi-tab Excel workbook. Successful uploads open the saved cutoff.
  • The cutoff displays names in title case as Last Name, First Name. Saved cutoffs show the named payroll deduction columns. Preview applies filters to the table and KPI cards. Reset Filters sits next to Preview and returns all three dropdowns to Choose option while restoring all rows.
  • The demo cutoff has thirteen fictional employees across fourteen assignment rows. Select finalized rows and choose Download Selected to save one PDF per checked employee using the updated payslip layout. Each filename includes the employee ID, name, and cutoff dates. Click Reyes, Jordan in the demo table to open the matching Expenses and Payments profile.
  • Django checks the original Summary sheet or CSV at preview and save. Missing employee numbers, missing source totals, and small rounding discrepancies are shown as warnings. Incomplete or ambiguous employee rows, invalid hours, and source totals off by more than 0.01 hours block the import.
  • Attendance and payroll numeric cells accept thousands separators and Philippine peso formatting. Ambiguous numbers are flagged with an import error.
  • Choose Attendance Adjustment in the Payroll upload modal and select a saved cutoff, or open the saved cutoff’s upload menu and choose Attendance Adjustment. Both paths accept the same Summary format for a different source period. Matched hours are added to the selected cutoff, The matched employee’s Remarks show the hours added by category, and the source period is listed above the table. Re-uploading that source period replaces its adjustment.
  • The Hours summary shows separate totals for regular hours, overtime, night differential, breaktime, worked days off, and legal and special holiday hours and overtime. Totals follow the applied filters and show a dash when a value is missing. Affected boxes show the total above a small breakdown of base hours and adjustments. Select one employee and click Preview to compare each box with that row’s source hours.
  • The Needs Attention panel below the table starts collapsed with the affected employee count. Expand it to review a scrollable list of reasons and next actions. Saved attendance flags missing regular hours, and the demo also shows a duplicate-name example and a negative-net-pay example. On the first page of the demo, Sam Bautista has ₱695 gross pay and ₱950 in deductions, so the demo flags the −₱255 net pay.
  • Demo status badges and action icons stay aligned with each employee when filtering or changing pages. The negative-pay row shows Needs Attention.

Payroll calculation status

  • Available now. Upload the SMCO payroll register and deductions workbook through the draft API. Django uses the register’s hours and rates to calculate gross pay, deductions, and net pay, then compares those amounts with the register. In the 16-row sample, gross pay and deductions matched. Two rows differed by ₱0.01 each in net pay.
  • Government deductions and tax. Payroll drafts can calculate SSS, PhilHealth, Pag-IBIG, and withholding tax when Payroll provides the employee type, applicable wage order and monthly contribution bases. Employee types marked exempt use zero withholding in the draft. A separate BIR comparison flags differences for review. Employer shares are reported separately.
  • Multiple detachments. Payroll drafts can use dated basic-pay assignments and the same employee ID across sites. Hour-based earnings stay with the site worked, and SSS and Pag-IBIG deductions are split by each site’s eligible earnings. Expenses go to the highest-hours site first, using pay available after its government deductions. Blank expense amounts display as zero. Other unavailable values appear as a dash. The demo shows a normal two-site payroll and a separate spillover example for a fictional guard.
  • Finalized payroll and loan balances. Finalized payroll drafts preserve the basic earnings used for the October 31 estimate and calendar-year 13th-month accrual. Each loan keeps its own installment and payment history, and automatic deductions stop at payoff. Open Expenses and Payments to search by employee ID or name and review loan types, matched payments, and expenses. Payroll also links to 13th-month accrual and draft status.
  • Attendance-to-payroll is pending. Uploading a DTR or attendance Summary saves employee hours for the cutoff screen. The proposed first phase will compare normalized names within a cutoff, with reviewer confirmation for duplicates or unresolved rows. The current draft API uses hours and rates from the separate payroll register.
  • Frontend and production workflow. The draft review screen, production approval, and real payslips are pending. Finalize and Download Selected on the demo cutoff use sample data.

API routes

Django registers eight API routes with ten GET and POST operations. See the main URL configuration and the tasks URL configuration.

Attendance and payroll drafts require an authorized session. Send the session cookie and CSRF token with authenticated POST requests.

GET /api/auth/csrf/
Get a CSRF token.
POST /api/auth/login/
Sign in and start a Django session.
POST /api/attendance/preview/
Preview Summary rows from a multipart upload in the file field.
GET /api/attendance/
List saved attendance cutoffs.
POST /api/attendance/
Submit attendance JSON to save or revise a cutoff.
GET /api/attendance/<cutoffId>/
Retrieve a saved cutoff and its employee rows. Open the SMCO sample.
POST /api/payroll/drafts/
Calculate and save a payroll draft from multipart uploads in the register and deductions fields.
GET /api/payroll/drafts/<draftId>/
Retrieve a saved payroll draft with totals, warnings, and per-employee issues. Each issue includes a reason and next action.
GET /api/tasks/
List demo tasks.
POST /api/tasks/
Create a demo task.

Run this command to query the demo tasks API while Django and Angular are running.

curl -fsS -H 'Accept: application/json' http://127.0.0.1:4200/api/tasks/

View the handlers for session authentication, attendance, payroll drafts, and demo tasks.
