VicanHR development summary

Local payroll and attendance workflow · November 19, 2026

Frontend developer handoff

Backend

  • Django and PostgreSQL run locally through Docker Compose.
  • Session login supports admin, finance, HR, and operations. Admin and finance can submit attendance and access payroll drafts.
  • Attendance uploads use the Excel Summary tab or structured JSON. Revisions update matching employees in the same detachment and cutoff.
  • The SMCO draft API calculates gross pay, deductions, and net pay from uploaded workbooks. See the payroll calculation status below for the sample results and remaining work.

Frontend

  • The login screen fits the browser viewport and connects to Django.
  • Upload a Summary CSV or a multi-tab Excel workbook. Successful uploads open the saved cutoff.
  • The cutoff displays names as Last name, First name. Preview applies filters to the table and KPI cards. Reset Filters sits next to Preview and returns all three dropdowns to Choose option while restoring all rows.
  • The demo cutoff has eight fictional employees, including five restored from earlier test data. Select finalized rows and choose Download Selected to save one PDF per checked employee using the updated payslip layout. Each filename includes the employee ID, name, and cutoff dates.
  • The Remarks column shows why a row needs attention. The panel below the table starts collapsed with the affected employee count. Expand it to review a scrollable list of reasons and next actions. Saved attendance flags missing regular hours, and the demo also shows a duplicate-name example.

Payroll calculation status

  • Available now. Upload the SMCO payroll register and deductions workbook through the draft API. Django uses the register’s hours and rates to calculate gross pay, deductions, and net pay, then compares those amounts with the register. In the 16-row sample, gross pay and deductions matched. Two rows differed by ₱0.01 each in net pay.
  • Attendance-to-payroll is pending. Uploading a DTR or attendance Summary saves employee hours for the cutoff screen. The proposed first phase will compare normalized names within a cutoff, with reviewer confirmation for duplicates or unresolved rows. The current draft API uses hours and rates from the separate payroll register.
  • Frontend and production workflow. The draft review screen, production approval, and real payslips are pending. Finalize and Download Selected on the demo cutoff use sample data.

API routes

Django registers eight API routes with ten GET and POST operations. See the main URL configuration and the tasks URL configuration.

Attendance and payroll drafts require an authorized session. Send the session cookie and CSRF token with authenticated POST requests.

GET /api/auth/csrf/
Get a CSRF token.
POST /api/auth/login/
Sign in and start a Django session.
POST /api/attendance/preview/
Preview Summary rows from a multipart upload in the file field.
GET /api/attendance/
List saved attendance cutoffs.
POST /api/attendance/
Submit attendance JSON to save or revise a cutoff.
GET /api/attendance/<cutoffId>/
Retrieve a saved cutoff and its employee rows. Open the SMCO sample.
POST /api/payroll/drafts/
Calculate and save a payroll draft from multipart uploads in the register and deductions fields.
GET /api/payroll/drafts/<draftId>/
Retrieve a saved payroll draft with totals, warnings, and per-employee issues. Each issue includes a reason and next action.
GET /api/tasks/
List demo tasks.
POST /api/tasks/
Create a demo task.

Run this command to query the demo tasks API while Django and Angular are running.

curl -fsS -H 'Accept: application/json' http://localhost:4200/api/tasks/
