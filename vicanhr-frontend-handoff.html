spreadsheet_number normalizes numeric attendance cells, source totals, payroll register values, and deductions. For example, ₱1,234.50 reads as 1234.50. Payroll accepts accounting negatives. Invalid grouping, decimal commas, and percentage text block the import.

Payroll drafts accept optional multipart statutoryInputs JSON. See the backend guide for the request example. Each matched employee returns statutory with treatment, withholding, and employee and employer contributions. The draft returns statutorySchedule with dates, contribution collection assumptions and taxExemptEmployeeTypes. A listed type overrides withholding for the draft while birComparison retains the statutory result when available. Build the payroll draft review

  1. Add a payroll draft entry point on the payroll dashboard. Require two .xlsx files labeled Payroll register and Deductions workbook.
  2. Submit FormData to POST /api/payroll/drafts/ with fields register and deductions. Follow the session and CSRF flow in Frontend/src/app/backend.ts. Use payroll-specific wording for authorization errors. Admin and finance have access.
  3. Open the review using the returned draftId. Load it with GET /api/payroll/drafts/<draftId>/ so it can be refreshed. A new draft returns HTTP 201 and an identical upload returns the existing draft with HTTP 200.
  4. Show the period, workbook filenames, employee count, calculated and register totals, and issue counts. Display the top-level warnings, including the note about using SSS values from the register.
  5. Show employee name, register row, calculated amounts, register amounts, and signed differences. Highlight nonzero differences and flag deductionsMatched: false. Add filters for both flags.
  6. Include loading, upload validation, session or role errors, and a missing-draft state.

Use the selected browser File objects directly in the multipart request. The browser sets the multipart boundary.

const form = new FormData();
form.append('register', registerFile);
form.append('deductions', deductionsFile);
const draft = await postToBackend('/api/payroll/drafts/', form);

Draft response fields

  • summary.employeeCount, summary.rowsWithDifferences, and summary.rowsWithoutDeductionMatch are counts. A row can contribute to both issue counts. Offsetting differences can yield a zero total.
  • summary.calculatedTotals, summary.registerTotals, and summary.totalDifferences contain grossPay, totalDeductions, and netPay. Each amount is a two-decimal string. Display the totals returned by the API.
  • employees[] carries the same three calculated fields and corresponding registerAmounts and differences objects. Differences are calculated minus register using the amounts shown in the response.
  • A missing deduction match means no employee override matched in the deductions workbook. The draft still uses applicable register values.
  • Each employee has an issues array. Display each issue’s reason and action. The register_difference issue includes fields for the affected amounts. The deductions_match_missing issue asks the reviewer to verify the workbook match and confirm the deduction source. The negative_net_pay issue flags calculated net pay below zero, including when the register agrees. Stable code values can drive filters.
