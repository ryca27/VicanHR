VicanHR frontend handoff

Angular integration guide for the Django attendance and payroll APIs

Start here with the Django task list

Use /api/tasks/ to practice one read and one write before connecting attendance or payroll. Start the services using the connection steps. If you’re on Windows using the shared Mac, open the tunnel first.

  1. Open the task list through Angular. The browser makes a GET request. GET needs no payload or login. Expect HTTP 200 with a JSON array. [] means Django responded and the table is empty.
  2. Read it from Angular code. Use the relative URL so the Angular proxy sends the request to Django. Each task has id, title, completed, and created_at. 
    const response = await fetch('/api/tasks/');
if (!response.ok) throw new Error(`Task list failed (HTTP ${response.status})`);
const tasks = await response.json();
console.log(tasks);

    You can paste this in DevTools Console on the Angular page, then inspect the request and response in the Network tab.

  3. Try a write on your local database. POST creates a task. The payload is the JSON body you send. In Angular, import postToBackend from backend.ts. It serializes the object and supplies the CSRF header. 
    const task = await postToBackend('/api/tasks/', {
  title: 'API smoke test',
  completed: false,
});
console.log(task);

    Expect HTTP 201 with the new task, including its generated id and created_at. Reload the task list to see it. If the title is missing, expect HTTP 400 with a validation error for title.

If the Angular URL fails, check Django directly at port 8080, or at port 18080 on Windows through the tunnel. If Django works directly, check the Angular proxy target and restart Angular after changing VICANHR_API_URL.

For real integrations, use the same relative URLs and POST helper. Sign in before calling attendance or payroll. Send files as FormData with the exact field names listed in the API reference. The task example is defined in Django’s task_list handler and TaskSerializer.

Connect Angular to Django

  1. Start the services. Run docker-compose -f Backend/compose.yaml up --build -d from the repo root, then run npm ci and npm start -- --host 127.0.0.1 --port 4200 in Frontend/. If Django runs on the shared Mac, use the Windows tunnel instructions.
  2. Check the proxy. Open /api/auth/csrf/ on port 4200 and look for csrfToken. In Angular, use relative /api/… URLs. The proxy defaults to Django on port 8080 and reads VICANHR_API_URL when Angular starts.
  3. Sign in through Angular. Use an admin or finance account on /login. Same-origin requests send the session cookie. Use postToBackend for writes because it fetches a CSRF token and adds X-CSRFToken. Pass a plain object for JSON or a FormData instance for uploads. Let the browser set the multipart boundary.
  4. Verify access. In the signed-in browser, open /api/attendance/. Expect an array of saved cutoffs, which can be empty on a fresh database. If it returns 403, check the session and account role. For POST requests, also check the CSRF token and cookie.

Jump to the route and payload reference or the payroll upload example. For a local Django backend on port 8080, open Swagger UI and its OpenAPI schema.

Local setup

Docker Compose installs Python dependencies from Backend/requirements.txt. Git now ignores Backend/venv/. If your IDE uses that folder as its Python interpreter, check the interpreter after pulling this change and recreate the environment from Backend/requirements.txt if needed.

Start Django and PostgreSQL with Docker Compose, then start Angular on port 4200. Use 127.0.0.1:4200 consistently so browser session cookies use the same hostname. The repository README has startup commands and local account setup. Open the Angular login or check the Django tasks endpoint.

Connect Windows to the shared backend

Django and PostgreSQL run on the host Mac. Angular runs on Windows. Both computers need to be on the same private network for this address to work.

  1. On the Mac, start the backend. With Colima running, open Terminal at the repository root and run:

    docker-compose -f Backend/compose.yaml up --build -d
curl -fsS http://127.0.0.1:8080/api/auth/csrf/

    The response should contain csrfToken. Keep the Mac awake while testing.

  2. On the Mac, allow SSH access. Open System Settings → General → Sharing → Remote Login. Turn it on and choose Only these users. Use a Standard macOS account authorized for the developer. Share its short username and the Mac’s private network address directly with the developer.

  3. On Windows, open the SSH tunnel in PowerShell. Replace mac-user and mac-address with the details from the host.

    ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:18080:127.0.0.1:8080 skippynutella@192.168.254.124

    Leave the PowerShell window open after SSH authenticates. Open the tunnel check on Windows and look for csrfToken. If SSH times out, check the private network connection and Remote Login on the Mac.

  4. On Windows, start Angular in a second PowerShell window. From the repository root, make sure your checkout has the updated Frontend/angular.json and Frontend/proxy.conf.cjs, then run:

    cd Frontend
npm.cmd ci
$env:VICANHR_API_URL = 'http://127.0.0.1:18080'
npm.cmd start -- --host 127.0.0.1 --port 4200

    Open the VicanHR sign-in page and use rctabernilla with its existing Django password. Open a saved cutoff that also appears on the Mac to confirm both machines are using the same PostgreSQL records. Saved changes are visible to both developers.

API routes and backend locations

Start in Backend/config/urls.py. Call the routes as relative URLs from Angular. Attendance and payroll draft APIs require an active admin or finance session. The role check lives in Backend/attendance/permissions.py.

Where Angular builds and sends POST payloads

  • Shared sender. postToBackend(path, payload) fetches the CSRF token, sends cookies, and passes FormData through or serializes the payload as JSON. See backend.ts.
  • Login. onSubmit() reads the login form with getRawValue() and posts its JSON to /api/auth/login/. See login.ts.
  • Attendance preview. The file picker builds FormData with the original file and posts it to /api/attendance/preview/. See file-box.ts.
  • Attendance save and adjustment. submitForm() builds one FormData per file and posts each to /api/attendance/. Adjustment requests also send type=attendance_adjustment and cutoffId. See upload.ts.
  • Payroll writes. Draft creation, finalization, loan creation, and payment entry are called directly through the Django API today. The payload fields and routes are in the backend API guide.

Connect payroll draft upload

  1. Add a payroll draft entry point on the payroll dashboard. Require two .xlsx files labeled Payroll register and Deductions workbook.
  2. Submit FormData to POST /api/payroll/drafts/ with fields register and deductions. Follow the session and CSRF flow in Frontend/src/app/backend.ts. Use payroll-specific wording for authorization errors. Admin and finance have access.
  3. Navigate to the existing /payroll/drafts/<draftId> review using the returned draftId. The review reloads via GET /api/payroll/drafts/<draftId>/. Treat HTTP 201 and 200 as success. A repeated upload with the same inputs and loan plan can return the existing draft.
  4. Show the period, workbook filenames, employee count, calculated and register totals, and issue counts. Display the top-level warnings, including the note about using SSS values from the register.
  5. Show employee name, register row, calculated amounts, register amounts, and signed differences. Highlight nonzero differences and flag deductionsMatched: false. Add filters for both flags.
  6. Include loading, upload validation, session or role errors, and a missing-draft state.

Use the selected browser File objects directly in the multipart request. The browser sets the multipart boundary.

const form = new FormData();
form.append('register', registerFile);
form.append('deductions', deductionsFile);
const draft = await postToBackend('/api/payroll/drafts/', form);

Draft response fields

  • summary.employeeCount, summary.rowsWithDifferences, and summary.rowsWithoutDeductionMatch are counts. A row can contribute to both issue counts. Offsetting differences can yield a zero total.
  • summary.calculatedTotals, summary.registerTotals, and summary.totalDifferences contain grossPay, totalDeductions, and netPay. Each amount is a two-decimal string. Display the totals returned by the API.
  • employees[] carries the same three calculated fields and corresponding registerAmounts and differences objects. Differences are calculated minus register using the amounts shown in the response.
  • A missing deduction match means no employee override matched in the deductions workbook. The draft still uses applicable register values.
  • Each employee has an issues array. Display each issue’s reason and action. The register_difference issue includes fields for the affected amounts. The deductions_match_missing issue asks the reviewer to verify the workbook match and confirm the deduction source. The negative_net_pay issue flags calculated net pay below zero, including when the register agrees. Stable code values can drive filters.
